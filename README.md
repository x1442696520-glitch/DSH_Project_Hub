# DSH Project Hub

DSH 插件：在当前 Workspace 中管理项目资料、任务和文件，并可选地连接企业微信 AI Bot 或飞书机器人。

> 插件运行需要兼容的 DeepSeek Harness（DSH）Host。项目资料保存在 DSH Workspace 中；机器人凭证和绑定信息保存在 Host 的操作系统凭证库中，或由 Host 环境变量提供。本仓库不应包含任何实际凭证、用户消息或项目数据。

## 功能

- **一 Workspace 一个项目**：使用 Workspace 根目录的 `project.md`、`tasks/` 和 `files/`；首次使用时需在当前 Workspace 的 Project Hub 面板中明确点击初始化，复用当前会话。插件启动不会在其他 Workspace 创建或写入项目；为恢复已打开项目助手的专属工具，Host 只读核对活动 Agent 的 Workspace/项目归属。普通启动和当前 Workspace 初始化不会自动创建、重命名 DSH Session，也不会给会话注入欢迎提示。绑定的项目助手会话按作用域额外注册 `project_hub_integrations`（飞书/企微）和 `project_hub_manage`（当前 Agent 的 DSH 工具清单诊断、当前 Workspace 的只读 Git 变更检查、项目/任务查看与按用户要求记录）工具；两者不做全局注册、不注入项目角色提示，也不限制或替换 DSH 原有代码、文件和终端工具。项目/任务仍由面板管理，Agent 可在用户明确要求时新增任务或记录节点/阻塞。恢复时按最近持久化请求恢复 `run_code`/PTC 模式，并校验历史工具。
- **目录迁移边界**：仅在用户确认后创建新的 DSH Workspace 和项目助手 Session；新 Session 继承原 Session 的 Agent preset（工具与提示配置），并校验继承结果，避免静默改变会话能力。旧 Workspace 保留为备份，不会删除，其他文件和 `files/` 附件不会自动复制或合并。
- **项目视图**：概览、任务看板和甘特图；支持负责人、进度、状态和日期调整；看板可搜索任务名称、负责人和事项，按逾期/未排期筛选，并批量修改状态；新建任务默认从本地当日开始、次日截止。
- **项目文件**：仅浏览当前 Workspace 的 `files/`；支持安全路径校验、受限文件读写和发送文件给已绑定的企业微信/飞书私聊。
- **CSV 导入与导出**：导出适用于 Excel 和飞书表格的 UTF-8 CSV，并防范公式注入；导入前可预览，每次最多新增 200 项，已有任务 ID 会跳过。历史节点不会在导入时重建；当前事项和阻塞卡点会导入为任务节点。
- **企业微信 AI Bot**：通过官方 SDK 的 WebSocket 长连接接收获准单聊消息；支持配对、文本投递和文件保存。可单独开启回复同步；已绑定的助手会在收到消息时自动恢复。
- **飞书机器人**：通过官方 Node.js SDK 长连接接收事件；支持单聊配对、项目选择、文本投递、文件保存；已绑定的项目助手会在收到消息时自动恢复。
- **文件处理边界**：收到的企微/飞书附件保存到项目 Workspace 的 `files/`，默认**不会读取文件内容或自动发给模型**。目前代码设置了每个入站文件最大 50 MiB、单条飞书消息最多 5 个文件且总计不超过 100 MiB；向机器人发送文件的插件上限为 20 MiB。平台本身可能另有规则。

群聊接入、读取聊天历史以及读取或修改云文档/表格不属于当前支持范围。普通个人微信号机器人接入也未实现。

## 运行要求

- DeepSeek Harness 插件 Host（DSH 公共插件 API）。
- Node.js 20 或更高版本；建议使用 DSH 随附的 Node.js 运行时。
- pnpm（`pnpm-lock.yaml` 为依赖锁定文件）。
- 配置企业微信或飞书机器人时，需在对应平台创建应用并授权相应能力。平台侧权限和限制以官方最新文档为准。

## 安装

从 GitHub 克隆仓库后，在仓库目录执行：

```powershell
pnpm install --frozen-lockfile
pnpm run build
pnpm run doctor
```

然后在 DSH 插件管理界面选择「安装本地目录」，指向克隆后的仓库目录，并启用 `dsh-project-hub`。每次更新插件后重新运行 `pnpm run build`，再从插件管理界面重新加载插件。

## 机器人凭证

优先在 Project Hub 的「办公集成」页配置凭证。Host 会尝试将其保存到当前操作系统凭证库；凭证值不会返回给浏览器。也可在启动 DSH Host 的进程环境中配置变量：

| 环境变量 | 用途 |
| --- | --- |
| `WECOM_AIBOT_ID` | 企业微信智能机器人 Bot ID |
| `WECOM_AIBOT_SECRET` | 企业微信智能机器人 Bot Secret |
| `FEISHU_APP_ID` | 飞书企业自建应用 App ID |
| `FEISHU_APP_SECRET` | 飞书企业自建应用 App Secret |
| `FEISHU_TENANT_KEY` | 可选；限定飞书租户 |
| `WECOM_DSH_SESSION_ID` | 旧式企微环境配置：绑定目标 DSH Session；优先使用页面配对 |
| `WECOM_ALLOWED_USER_IDS` | 旧式企微环境配置：允许的 UserID，逗号分隔；优先使用页面配对 |

如凭证库和环境变量同时配置，已保存的凭证库条目优先。环境变量仅由 Host 进程读取；设置或修改后需重启 DSH Host。**不要把真实 Secret 写入 `.env`、代码、Issue、截图或聊天消息，也不要提交到 GitHub。**

企微和飞书均使用各自的平台 API/SDK，不要求公网回调服务；Host 需要能够主动访问相应平台的网络服务。配对采用一次性、限时验证码，只有已绑定的私聊用户才能路由到项目会话。

只要 DSH Host 正在运行，已绑定且通过用户授权的企微/飞书私聊消息会自动尝试恢复对应的项目助手会话，无需手动打开会话窗口。插件会核验唯一工作区归属、项目绑定和会话工作目录；恢复时仅将 `project_hub_integrations` 注册到该 Agent 的工具作用域，并验证历史请求中声明的 DSH 工具仍可用（不再恢复旧版项目/任务管理工具），校验通过后才记录去重并投递。若 Host 未运行、恢复能力不可用、历史工具缺失或其他配置校验失败，消息会拒绝投递并提示检查/打开 DSH 会话后重发，避免静默启动一个缺少历史工具的 Agent。自动恢复仍不保证还原原会话专属模型或所有自定义提示配置。

`pnpm run doctor` 会检查 Node.js 版本、插件依赖（包括 Windows 凭证库原生模块）、构建文件和当前可解析的 DSH Host API；报告不包含凭证内容。也可在「办公集成」页面点击「检查运行环境」查看 Host 服务和机器人连接状态。

## 安全与数据边界

- 默认拒绝未绑定用户；不把收到的聊天、文件或文档内容全量同步到项目之外。
- 入站文件写入当前会话所属 Workspace 的 `files/`，并使用 DSH Workspace 路径边界与沙箱策略；重复文件名需要明确确认覆盖。
- 连接器日志避免记录凭证和完整消息内容；请勿在公开仓库、Issue 或 CI 日志中放入用户数据或密钥。
- 详见 [`SECURITY.md`](SECURITY.md)。
